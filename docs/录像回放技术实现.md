# 录像回放技术实现说明

本文档说明 video-mid 中「按天 24 小时时间轴 + 按需拉流」录像回放的完整技术实现，覆盖数据落盘、后端接口、前端工具包与业务集成。

---

## 1. 目标与约束

### 1.1 产品目标

- 选定设备、选定日期后，展示当天 **00:00:00 ~ 23:59:59** 的录像时间轴。
- **绿色**：有录像，可点选 / 拖拽定位；**灰色**：无录像，不可点、不可拖。
- 播放器底部固定全天时间轴（影视机风格），支持滚轮缩放、框选放大、绿段拖拽选时。
- **按需拉流**：只加载当前正在播放的那一个文件；禁止预加载全天录像。

### 1.2 硬性约束

| 约束 | 实现要点 |
|------|----------|
| 无起止时间选择框 | 仅日期；查询窗口固定为当日全天 |
| 灰区锁死 | `hitSegment` 未命中则不 seek；灰底 `pointer-events: none` |
| 单路 `src` | 切换前 `unloadVideo`；同一时刻仅 1 个 `<video>` |
| `preload="none"` | 播放器与 `loadAndPlayOne` 均强制 none |
| 轴在画面下方 | `.rdt-player-footer` 挂载 `DayTimelineBar` |
| 去掉原生分片进度 | 无 `controls`，避免 xx/300 类控件 |
| 只读 | 工具包不提供录像增删改 |

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│  业务页（DevicesView 弹层 / BizPortalView）                    │
│  RecordingPlaybackPanel → RecordingDayTimeline               │
└───────────────┬─────────────────────────────┬───────────────┘
                │ 元数据列表                     │ 视频字节
                ▼                               ▼
     GET .../recordings?from&to          GET .../recordings/{id}/{file}
                │                               │
                ▼                               ▼
         RecordFileService.list*          RecordFileService.openFile
                │                               │
                └───────────┬───────────────────┘
                            ▼
              {output-dir}/{deviceId}/yyyyMMdd_HHmmss.mp4
```

**分层职责**

| 层 | 职责 |
|----|------|
| 落盘 | `MainStreamRecordTestTool`（或其它录像源）按设备目录写 MP4 |
| 后端 | 按设备 + 时间窗列文件；安全打开文件流 |
| 工具包 | 日期 → 段映射 → 时间轴交互 → 按需 `video.src` |
| 业务页 | 注入 `fetchRecordings` / `getVideoUrl`，弹层或业务端嵌入 |

## 3. 数据落盘

### 3.1 目录结构

配置项（`application.yml`）：

```yaml
testdata:
  main-stream-record:
    enabled: true                    # 是否启用测试录像工具
    output-dir: data/testdata-records
    interval-seconds: 300
    clip-seconds: 300                # 单段默认时长，与前端 clipSeconds 对齐
    ffmpeg-path: ffmpeg
    zlm-http-port: 8080
```

落盘布局：

```
{output-dir}/
  {sanitized_device_id}/
    20260915_143000.mp4
    20260915_143500.mp4
    ...
```

- 文件夹名 = 设备业务 ID（`device_id`，经 sanitize）。
- 文件名 = `yyyyMMdd_HHmmss.mp4`，时间戳表示该段**开始时间**。
- 若接口无结束时间，前端用 `clipSeconds`（默认 300）推算绿段结束。

### 3.2 写入组件

- 类：`com.jizhi.videomid.tools.MainStreamRecordTestTool`
- 行为概要：定时对主码流用 ffmpeg 截取固定时长片段，写入上述目录。
- 生产环境可替换为真实 NVR/边缘录像同步，只要保持「设备目录 + 时间戳文件名」约定，列表逻辑无需大改。

## 4. 后端实现

### 4.1 核心服务

**文件：** `src/main/java/com/jizhi/videomid/record/RecordFileService.java`

| 方法 | 作用 |
|------|------|
| `list(deviceId, from, to)` | 扫描设备目录 MP4，按文件名时间过滤、倒序 |
| `listWithVideoUrls(..., publicBaseUrl)` | 在 list 结果上追加 `videoUrl` |
| `openFile(deviceId, fileName)` | 安全打开文件为 `Resource`（防路径穿越） |

列表项字段示例：

```json
{
  "deviceId": "CAM_EAST_01",
  "fileName": "20260915_143000.mp4",
  "timestamp": "20260915_143000",
  "recordTime": "2026-09-15 14:30:00",
  "size": 1234567,
  "path": "...",
  "videoUrl": "http://host:8090/api/open/recordings/CAM_EAST_01/20260915_143000.mp4"
}
```

`from` / `to` 支持：`yyyyMMdd_HHmmss`、`yyyy-MM-dd HH:mm:ss`、ISO、纯日期。

### 4.2 接口一览

#### 管理端（需登录 JWT）

**控制器：** `RecordFileController`  
**前缀：** `/api/recordings`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/recordings?deviceId=&from=&to=` | 列表（**无** videoUrl） |
| GET | `/api/recordings/{deviceId}/{fileName}` | 直出 MP4；`<video>` 可用 `?token=` |

鉴权：`AuthInterceptor` 拦截 `/api/**`；`AuthController.extractToken` 支持 Header `Bearer` 与 Query `token`（因 video 标签无法带 Authorization）。

#### 开放接口（免登录）

**控制器：** `OpenApiController`  
**前缀：** `/api/open`（`WebMvcConfig` 排除鉴权）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/open/devices/{deviceId}/recordings?from=&to=` | 列表 + `videoUrl` |
| GET | `/api/open/recordings/{deviceId}/{fileName}` | 公开 MP4 |

`videoUrl` 前缀：`open-api.public-base-url`；为空则按当前请求拼 scheme/host/port。

#### 业务端（需登录）

**控制器：** `BizPortalController`  
**前缀：** `/api/biz`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/biz/devices/{deviceId}/recordings?from=&to=` | 带 `videoUrl`；**已停用**设备拒绝回放 |

业务规则：已停用设备灰色可见但不可播（含回放）。

### 4.3 安全要点

- `openFile`：规范化路径，`startsWith(设备根目录)`，拒绝 `..`、非法文件名。
- 文件名必须匹配 `yyyyMMdd_HHmmss.mp4` 模式（与服务内校验一致）。
- 开放接口无鉴权，生产环境应限制内网或另加签名/白名单。

## 5. 前端工具包

**目录：** `web/toolkits/recording-day-timeline/`  
**包名：** `@video-mid/recording-day-timeline`  
**入口：** `src/index.js`

### 5.1 模块职责

| 模块 | 文件 | 职责 |
|------|------|------|
| 主组件 | `RecordingDayTimeline.vue` | 日期、拉列表、播放器壳、底部时间轴 |
| 时间轴 | `DayTimelineBar.vue` | 缩放 / 平移 / 绿段拖拽 / 刻度 |
| 播放器 | `OnDemandVideoPlayer.vue` | 单路 `<video preload="none">` |
| 拉流工具 | `onDemandPlay.js` | unload / loadAndPlayOne / 禁止预取 |
| 时间工具 | `timeUtils.js` | 日界、段合并、命中、选文件 |
| 缩放工具 | `timelineZoom.js` | zoomAt / pan / ticks / 坐标换算 |

### 5.2 `RecordingDayTimeline` 接口

**Props**

| Prop | 类型 | 说明 |
|------|------|------|
| `deviceId` | string | 必填 |
| `initialDate` | string | `yyyy-MM-dd`，默认今天 |
| `clipSeconds` | number | 无 endTime 时默认段长，默认 300 |
| `fetchRecordings` | `(id, {from,to}) => Promise<record[]>` | 必填，注入列表接口 |
| `getVideoUrl` | `(id, fileName, record) => string` | 必填，解析可播 URL |
| `showPlayer` | boolean | 是否内置播放器，默认 true |

**Events：** `play` / `seek` / `loaded` / `error` / `date-change`  
**Expose：** `reload` / `playAt` / `segments` / `date`

### 5.3 绿段构建（`timeUtils.js`）

```
records[]
  → 解析 recordTime / timestamp / startTime
  → 过滤到当日
  → end = endTime 或 start + clipSeconds
  → 按 startSec 排序并合并重叠区间 → segments[]
```

关键字段：`startSec` / `endSec` / `records[]`（合并后多文件） / `leftPct` / `widthPct`。

- `hitSegment(segments, sec)`：点是否落在绿段（灰区返回 null）。
- `pickRecordAt(segment, sec)`：段内按开始时间选中具体文件。
- `earliestSegment`：「播放」按钮起点。

### 5.4 按需拉流（`onDemandPlay.js`）

```
playAt(daySec)
  → hitSegment；未命中则 return
  → pickRecordAt → resolveUrl → seekInFile = daySec - 文件日始秒
  → playOne(url, seekSeconds)
       → 若同一文件已加载：只改 currentTime
       → 否则：unload → src=url → load → seek → play
```

| 规则 | 说明 |
|------|------|
| 单路 | 新 URL 前必 `removeAttribute('src')` + `load()` |
| 同文件拖拽 | 不重载，避免卡顿 |
| 预取 | `shouldPrefetchNext()` 恒为 `false` |
| 连播 | `ended` 后找下一段绿区再 `playAt` |

### 5.5 时间轴交互（`DayTimelineBar.vue`）

| 操作 | 行为 |
|------|------|
| 滚轮 | 以光标时间为锚点缩放（最小视窗约 10 秒） |
| 绿段按住拖拽 | 实时 scrub，rAF 合并 seek，触发换流/定位 |
| 拖到灰区 | 不生效，保持上次绿段位置 |
| 空白拖拽 | 框选放大；Alt/Shift+拖拽平移 |
| 双击 /「全天」/ Esc | 还原 0–24h |
| 放大刻度 | 由视窗跨度自动切到分、秒级（`buildTicks`） |

播放头仅在绿段上可抓取；灰区播放头不可拖。

### 5.6 布局结构（DOM）

```
.rdt-root
  .rdt-toolbar          （日期 / 播放 / 刷新）
  .rdt-player-shell
    .rdt-player-stage   （OnDemandVideoPlayer + 覆盖播放按钮）
    .rdt-player-footer  （DayTimelineBar ← 贴底全天轴）
```

样式全部 `rdt-` 前缀 + `scoped`，避免污染业务页。

## 6. 业务集成

### 6.1 `RecordingPlaybackPanel`

**路径：** `web/src/components/RecordingPlaybackPanel.vue`

- 封装工具包，提供关闭按钮。
- 默认走管理端：`GET /api/recordings` + `recordingFileUrl`（带 token）。
- 可通过 props 覆盖：
  - `fetchRecordings`
  - `getVideoUrl`

### 6.2 设备管理弹层

**路径：** `web/src/views/DevicesView.vue`

- 行操作「录像回放」→ 本页 `mask` 弹层嵌入 `RecordingPlaybackPanel`。
- **不**新开路由页。
- 遮罩关闭：需在遮罩上 pointerdown + pointerup，避免时间轴拖出弹窗外误关。

### 6.3 业务端

**路径：** `web/src/views/BizPortalView.vue`

- 目录树选设备 →「录像回放」弹层。
- 注入：
  - `fetchBizRecordings` → `/api/biz/devices/{id}/recordings`
  - `getVideoUrl` → 优先使用返回的 `videoUrl`（开放文件路径）
- 已停用设备：`playable=false`，回放按钮禁用；接口也会拒绝。

### 6.4 前端 API 封装

**路径：** `web/src/api/device.js`

| 函数 | 后端 |
|------|------|
| `fetchRecordings` | `GET /api/recordings` |
| `recordingFileUrl` | `/api/recordings/{id}/{file}?token=` |
| `fetchBizRecordings` | `GET /api/biz/devices/{id}/recordings` |

HTTP 基址：开发环境走 Vite 代理（`web/vite.config.js` → 后端），避免浏览器直连跨域。

## 7. 端到端时序

```
用户选日期 / 打开弹层
  → dayBounds → from/to = 当日 00:00:00 ~ 23:59:59
  → fetchRecordings(deviceId, { from, to })
  → buildDaySegments(records, date, 300)
  → 渲染灰底 + 绿段；无段则禁用播放

用户点「播放」或绿段拖拽/点选
  → hitSegment(sec)；灰区忽略
  → pickRecordAt → URL + 文件内 seekSeconds
  → unload 旧流（若换文件）→ loadAndPlayOne
  → timeupdate：playheadSec = 文件日始 + currentTime

当前文件 ended
  → 查找 playhead 之后的下一段 → playAt（仍按需，不预取）
```

## 10. 本地验证建议

1. 确认 `output-dir` 下有对应 `deviceId` 的 mp4。
2. 管理端设备列表 →「录像回放」：绿段可拖，灰段无效；切换时段 Network 仅出现当前文件请求。
3. 业务端：已停用设备不可开回放；已启用可开。
4. Demo（可选）：`cd web/toolkits/recording-day-timeline && npm run demo` → http://localhost:5199/

## 11. 扩展注意

- 若真实录像有明确结束时间，在列表中返回 `endTime`，工具包会优先使用，而不再依赖 `clipSeconds`。
- 若改为对象存储，只需替换 `RecordFileService` 的 list/open（或改 `getVideoUrl` 为签名 URL），时间轴与按需播放逻辑可复用。
- 同设备多通道录像时，建议仍按 `deviceId` 分目录，或在文件名中扩展通道维度并在 `list` 中过滤。
